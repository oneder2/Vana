# 当前架构与数据契约

适用版本：0.7.0，2026-10-12 修复后的主线。旧 PRD、Git Sync Protocol 属于历史设计，不代表当前实现。

## 数据路径

React/Tiptap → 按账号和文档分组的草稿服务 → Tauri 文档命令 → SQLite 事务 → compact outbox → Supabase revision RPC。

已有文档默认以阅读模式打开，新建文档直接进入编辑。阅读模式关闭 Tiptap 编辑、格式工具及标签修改；进入阅读前提交草稿，失败时保留编辑状态。它是客户端防误改交互，不是访问控制；当前没有协作者或共享链接权限模型。浏览文档/分组不保存正文；原生保存接口对语义相同的正文及相同标题、文本、标准化标签直接返回原记录，不改时间、历史或 outbox。

- `src/lib/documentDrafts.ts` 在编辑器卸载后继续保存；失败保留快照并阻止导航/关闭。
- `src-tauri/src/db/accounts.rs` 管理空间定位、旧库迁移和账号标识校验。
- `src-tauri/src/db/documents.rs` 管理领域写入及整棵子树事务。
- `src-tauri/src/db/sync.rs` 管理一致性导出、远端应用、目录验证、冲突副本和确认。
- `db.rs` 定义 IPC 契约、schema、查询、标签、恢复和存储策略；仍可进一步拆分。
- `src/lib/supabaseSync.ts` 负责认证及协议编排，网络失败通过 Promise rejection 反馈。

## 空间与迁移

应用数据目录下的 `vana-local/control.db` 保存全局连接配置、会话、首次启动状态。`space-guest.db` 保存访客文档；`space-<SHA256(project URL + user UUID)>.db` 保存每个项目/用户的文档、标签、历史、队列和同步状态。退出登录返回访客空间，不会把账号文档暴露给访客。

写入和同步携带预期空间标识。已经切换空间的迟到请求会被拒绝；进入事务后连接固定到原空间，不能写到新账号。切换账号或连接配置前先提交所有草稿。

旧 `vana.db` 保留原文件。若旧配置记录了合法的用户 UUID 和项目 URL，复制到该账号空间；否则复制到 `legacy-unassigned.db`，不会自动绑定到新登录账号。设置中的恢复入口会明确复制数据、生成新 ID、保留层级并进入当前空间队列。访客文档同样需要明确复制。每个来源在每个目标空间最多导入一次。非法旧 JSON 恢复为包含原始字节的代码块，不丢弃原数据。

空间标识是路由与一致性边界，不是本机用户访问控制或加密边界。

## 事务、任务与保留策略

一次领域操作在一个 `IMMEDIATE` 事务中更新文档、标签、历史及任务。目录移动的深度超限、循环、无效父节点和任何写入失败都会回滚。状态和深度变更为每个受影响节点生成任务。单独恢复子节点时，若父节点状态不匹配，将恢复的子树移到根层。

每篇文档最多保留一个待处理任务；任务只保存 mutation UUID，正文从一致性快照读取。新的编辑获得新任务 ID 和 mutation UUID，所以旧网络确认不能删除后来的任务。确认只更新远端基准 revision，不覆盖当前正文。正文另外携带本地 content generation；在远端版本应用前产生、应用后才落库的内存草稿会保存为新冲突文档并通知用户，不能用新 revision 覆盖云端正文。

历史最多 20 个版本/文档、30 天，全空间最多 5 MiB；最先达到的条件生效。统计包含正文、历史、标签、队列 payload 和附件元数据，不等于 SQLite 文件在磁盘上的大小；SQLite 删除后会复用空闲页，原文件不会立即缩小。

`db/history.rs` 提供绑定账号空间与文档 ID 的正文记录查询。界面可预览版本，与打开记录时的正文切换对照，尚不能一键恢复。实际远端应用在原事务中保留变化前后的正文，并去掉相邻重复快照；不会因此创建上行任务。历史时间是本机记录时间，历史不上传，也不包含修改者身份、历史标题、标签或目录。有限本地记录不是防篡改的审计日志，无法显示本机尚未观察到或已淘汰的远端中间版本。

回收站可以永久删除整个子树：正文、关联标签、历史和附件元数据清除；保留很小的删除标记及待同步任务。服务端保留删除标记以拒绝旧设备复活。此操作不是磁盘安全擦除，保留的旧库备份也不会自动删掉。

Hosted 数量/总量/频率限制只用于内置 Hosted 的已登录空间。访客和自托管不受这些商业限制；所有模式仍有 512 KiB 正文技术上限。界面的 0 表示不设该类上限。Hosted 配额目前是客户端保护，不能作为服务端计费或防滥用保障。附件上传仍未实现。

## 同步协议 v2

1. 验证用户身份与当前项目/空间，提交待保存草稿。
2. 创建服务端固定快照，按 500 条分页完整拉取；分页过程不会受 `max_rows=1000` 或随后编辑影响。
3. 一次事务应用快照；验证父节点、类型、状态及深度。远端变更与本地待同步目录树重叠时，先复制完整受影响树并生成新 ID，再应用云端版本。界面提示冲突副本。
4. 导出待同步快照，调用 `vana_push_documents`。服务端按用户锁定树，原子检查每个 base revision 和 mutation UUID；任何过期 revision 拒绝整个批次。重复 mutation 是幂等请求。正文 JSONB 是对象，旧字符串仅在读取/迁移边界转换。
5. 写入由服务端分配全局 revision 和更新时间；客户端确认精确任务 ID。网络期间的新修改仍保留在 outbox。

并发冲突发生在拉取后、上行前时，此次同步报告失败且保留任务；下一次同步拉取后保留冲突副本。固定快照最多保留 10 分钟，同一账号最多 4 个同时存在；正常完成/失败会主动释放，过期快照在后续开启同步时清理。

客户端不再发常态目录 PATCH，也不回退到无条件 upsert。新服务端迁移撤销旧客户端直接写入权限，因此部署迁移后旧客户端同步会报错，应一起升级。未应用迁移的新客户端也会明确报错，保留本地数据。

## 安全边界

当前 SQLite 正文、历史、Supabase 正文以及全局会话/refresh token 都是明文。本地 Unix 数据目录限制为 0700；Windows/Android 使用应用目录权限。不要称为端到端加密、SQLCipher 或系统凭据保险库。`tauri-plugin-store` 保存的旧文件迁移密钥是 JSON 文件中的 Base64，不是系统 Keychain/Keystore。旧 `.enc` 文件的 AES-GCM 与当前 SQLite 文档不是同一存储路径。

Auth `/user` 成功返回有效 UUID 后才允许保存导入会话；云端读权限由 RLS 限定到 `auth.uid()`，写 RPC 不接受客户端声明的 owner。服务端管理员仍可读取云端数据。Anon key 是公开配置，service_role key 不应进入客户端。生产连接应使用 HTTPS。原生导出文件名、扩展名、写入碰撞及分享目录边界受到校验。

要抵御本机同一用户的恶意程序、XSS 或管理员，需要后续专门实施系统凭据库、CSP、数据库加密或端到端加密及密钥迁移，当前版本没有这些承诺。

## 验证

- `npm run typecheck && npm test && npm run build`
- `cargo test -j 2 --manifest-path tests/native-core/Cargo.toml`：引入实际后端源文件，仅替换 Tauri 路径解析器。
- `cargo check -j 2 --manifest-path src-tauri/Cargo.toml`
- `python3 scripts/test-supabase-protocol.py`：独立 Docker PostgreSQL、实际迁移、RLS、原子回滚、分页及并发写入。Auth 由测试 stub 提供，不等于托管 Supabase 部署验证。
- 浏览器验证真实 React/Tiptap，Tauri IPC 由受控 fixture 替代；不能据此声称原生 ACL 或真机分享已验证。
