# 文字冲印与信稿工坊

2026-10-18 · 开发分支 `feat/letterpress-studio`，尚未包含在公开版 0.7.1 中。

## 使用

1. 选中文字，桌面右键或 Android 系统选择工具栏可打开“文段分享”或“制作信稿”。也可打开一篇文档，在“更多文档操作 → 文字冲印与信稿”进入；桌面也可从文件菜单进入。选中文字时仅使用选中片段，否则使用当前正文。
2. 在“介质”选择分享卡片、书信、石碑、奥术或终端，以及 3:4、1:1、9:16 画幅。
3. 在“文字”调整标题、正文、落款、字体、字号、行距和对齐；介质页可调整文字留白与纹理。
4. 在“痕迹”选择工具，点按放置，或拖动决定方向和范围；也可用“添加一处”按钮放置后调整滑块。血迹有定向溅射、滴落、擦抹三种方式。
5. 选择痕迹可调整位置、方向、范围、浓度、形状和层次；支持删除、撤销和重做。
6. 点击“插入文档”，作品作为正文中的信稿块自动保存。块下“调整信稿”可再次打开，修改后点击“保存到文档”。也可独立保存 PNG，Android 打开系统图片分享。顶部“保存信稿”导出可再次打开的 JSON；Android 同样通过系统分享将信稿保存到文件应用或传给其他应用。

制作中的调整在工坊内预览，点击“插入文档”或“保存到文档”后写入正文；插入保留原文字，在选中段落之后添加信稿。信稿作为可编辑配方保存，跟随正文自动保存、修改记录、空间备份和可选同步。尚未插入的制作仅在本次会话缓存，跨重启应先插入文档或导出信稿 JSON。

## 介质与效果

效果记录的是位置、方向和种子等意图，渲染器按介质解释外观；切换介质不删除图层。

| 介质 | 血迹 | 烧焦 | 损毁 | 污渍 |
| --- | --- | --- | --- | --- |
| 分享卡片 / 书信 | 吸收扩散，擦抹边缘洇开 | 焦边和烧穿缺口 | 带纤维边缘的撕裂 | 吸收晕边与不规则沉积 |
| 石碑 | 沉积、流痕、断续擦抹 | 表面烟熏 | 裂纹与局部崩裂 | 深色沉积 |
| 奥术 | 深色血迹 | 紫色焦边与缺口 | 带亮边的裂隙 | 紫色侵染 |
| 终端 | 有高光的血滴与玻璃擦痕 | 玻璃灼痕与显示线 | 放射状碎屏 | 玻璃上的浅色污渍 |

焦边与裁切共享同一不规则轮廓，血滴包含凝结颗粒、纸纤维吸收与玻璃高光，污渍呈不规则晕边。痕迹按层次绘制。纸和奥术的缺失区域在最终合成时再次裁去，后加血迹或污渍不会把缺口填回；石碑和终端保留硬质表面。当前为程序化二维效果，不提供物理流体模拟或任意笔刷绘画。

纸张结合细粒纹理、长短纤维、纸浆色差和边缘旧化；书信带交叉折痕，卡片保留压纸切边。石碑结合细孔、矿脉与刻字明暗，奥术增加符文刻度和局部微光，终端呈现玻璃反光与边缘暗角。烧焦以烟晕、炭化边和灰屑分层呈现。纹理随配方种子固定，细粒纹理缓存最多 12 张，避免反复调整时重复生成像素数据。

工坊底部操作栏、预览底色和滚动条跟随当前主题。工坊与正文内的信稿使用透明衬底，纸边和损毁缺口透出所在界面的颜色；独立 PNG、PDF 与 DOCX 的图片继续使用固定衬底，作品导出不随应用主题改变。

## 导出与边界

- PNG 宽度固定 1080，画幅分别为 1080×1440、1080×1080、1080×1920。预览使用同一渲染器，较低分辨率绘制。
- 首版为单张作品。正文最多 12,000 个 UTF-16 字符，标题和落款各 120，最多 24 层痕迹；超出实际排版空间会阻止图片导出，不会默默截断。可以缩小字号、改用长幅或选取短片段。
- 信稿 JSON `version: 1` 保存正文、介质、画幅、字体选项、排版、纹理种子与有序痕迹。导入校验允许的选项、有限数值、文本长度和图层 ID；未知版本或非法配方保留当前制作不变。导入操作可撤销。
- 同一环境、相同字体和种子的画面可复现。跨设备的系统字体、文字测量与栅格化可能不同，不保证像素一致。
- “书刻”（ZCOOL XiaoWei）和“笔迹”（Ma Shan Zheng）随应用打包，无需远程字体服务；“清晰”和“电码”使用系统字体。来源与 OFL 许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。
- 材质、纹理和痕迹由本地 Canvas 绘制。信稿文件是包含正文的独立明文文件，正文中的配方纳入文档同步与空间备份；单独导出的 JSON 不会自动关联回文档。PNG 包含所见文字和效果。
- 正文 PDF 与 DOCX 导出保留信稿图片；Markdown 以 `vana-letterpress` 代码块保留完整配方，普通 Markdown 查看器显示配方文本。旧版 0.7.1 客户端不支持新内容块，含信稿的文档应在支持此功能的版本间使用。
- 桌面原生版写入既有导出目录且不覆盖同名文件；浏览器使用文件下载。Android 使用应用导出缓存和系统分享，不宣称已直接写入相册；应通过分享目标保存图片或信稿。
- 用户字体导入、外部图片材质、多页排版、个人预设库和在线作品社区不在首版范围。

## 实现

`src/lib/letterpress/model.ts` 定义可移植配方与导入边界；`render.ts` 处理介质、排版和合成；`export.ts` 连接浏览器下载与原生文件导出。`LetterpressStudio.tsx` 为按需加载的制作界面；`extension.ts` 提供 Tiptap `letterpress` 内容块，`document.ts` 处理配方与选区。原生正文校验接受受限的配方节点，无需数据库或云表迁移。Android 保留 WebView 原生 Floating ActionMode 和内容定位矩形，仅追加“文段分享”“制作信稿”，不再用网页菜单覆盖选区。原生导出增加 PNG / JSON 扩展名与 Android MIME 类型，沿用既有路径校验和防覆盖保存。
