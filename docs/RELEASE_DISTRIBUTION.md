# 官网与 GitHub Release 的职责

官网是用户入口，GitHub Release 是正式安装文件与版本历史的来源。两者使用同一批构建产物，避免安装包、版本号和签名分叉。

| 部分 | 负责内容 |
| --- | --- |
| 官网 | 产品介绍、界面展示、平台选择、最新稳定版下载、安装帮助、更新摘要 |
| GitHub Release | 按版本保存 APK / 桌面安装包、完整更新记录、校验文件、历史版本 |
| 发布流水线 | 编译、测试、签名、校验，准备 Release 草稿；正式发布后更新官网的下载清单 |

## 推荐流程

1. 候选版本通过验收，用版本标签触发现有发布流水线。
2. 流水线生成各平台安装包和校验信息，创建 GitHub Release 草稿。现有 `release.yml` 已采用草稿发布。
3. 核对安装包、签名和更新说明，正式发布 Release。
4. 由服务器定时读取最新正式 Release 更新静态下载清单。草稿和预发布版本不能覆盖稳定版入口。
5. 官网读取清单，显示版本和适合当前平台的下载按钮，同时保留其他平台及历史版本入口。

清单建议包含版本、发布时间、Release 页面 URL，以及每个平台的架构、文件名、下载 URL、SHA-256、最低系统要求。Android 可复用现有 `android-release-manifest.json` 中的哈希与签名证书信息；未来统一到跨平台清单。清单由官网服务器生成，官网无需逐个浏览器请求 GitHub API，也无需手工维护版本号。

先让官网下载按钮直接指向 GitHub Release 附件即可。若实际用户下载受限，再增加 CDN 或镜像；镜像复制原安装文件并校验哈希，不重新构建。GitHub 不可访问时，官网已有清单仍可展示版本信息，但直接下载仍依赖 GitHub 的可用性。

Android 所有正式分发渠道必须沿用同一签名密钥，才能覆盖升级。开发用 Preview 包独立于稳定版，不进入官网的默认下载入口。需要回退时，更新官网清单指向可用的历史版本，保留已发布历史文件；实际客户端能否降级须另行验证。

## 当前实现

官网已部署到 <https://vana.gellaronline.cc/>，使用静态 HTML、CSS 和原生浏览器脚本。服务器每 15 分钟读取 GitHub 最新正式 Release，验证版本、六种格式、来源与 SHA-256，原子替换页面；失败保留上次完整版本。当前默认版本以官网 `/release.json` 和 GitHub `/releases/latest` 为准，候选和 Preview 不进入该入口。正式 Release 提供 `SHA256SUMS.txt`，覆盖安装文件与 Android 构建清单；0.8.0 沿用此分发流程。

官网维护和回退见 [网站说明](../website/README.md)，0.8.0 内容见 [更新说明](RELEASE_NOTES_0.8.0.md)。此前发布流程证据保留在 [0.7.1 发布记录](RELEASE_0.7.1_2026-10-16.md) 和 [发布自检](RELEASE_READINESS_2026-10-15.md)。分发仍使用 GitHub 原文件，当前没有 CDN 安装包镜像或自动安装更新。
