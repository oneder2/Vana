# 阅读与账号界面优化

> 历史设计或验收记录，仅说明当时状态。当前功能与发布结论见 [文档索引](../README.md)。
## 设计方向

主题是个人文档与书签，服务日常阅读、写作和偶尔的跨设备登录。正文页的任务是让人找到并读写文档，账号页的任务是管理身份，设置页的任务是调整外观与保管备份。

沿用四主题，不另建装饰色板。默认奥术主题的六个令牌：底色 `#05040a`、面板 `#14111f`、边界 `#342d46`、正文 `#d9d3e5`、辅助文字 `#9a90ad`、强调 `#b7a3e8`。其他主题从同一主题系统映射；按钮与选中背景由这些令牌混色，不硬编码第二套颜色。

标题采用 Iowan Old Style / 思源宋体 / Noto Serif CJK 回退，界面与表单采用 Inter / Noto Sans CJK / 系统无衬线，代码与正文沿用文档排版令牌。无需在线下载字体。

布局草案：

```text
正文：  [文档库 / 目录 / 账号入口] │ [路径、编辑、修改记录]
                                   │ [居中的正文阅读宽度]
账号：  [返回文档]                 │ 账号
        [账号 ← 书签选中]         │ 身份 / 登录或注册
        [设置]                    │ 本机文档复制与退出
设置：  [返回文档]                 │ 设置
        [账号]                    │ 四主题预览
        [设置 ← 书签选中]         │ 备份 / 折叠的高级设置
手机：  [返回文档] → [账号 | 设置] → 当前页内容
```

自我评审：最初“账号卡片 + 多块功能卡片”的方向容易变成通用管理后台，改成窄导航与连续内容区，只有身份使用一块安静的底色。视觉选择集中在与目录位置对应的书签标记；没有加光晕、粒子背景、滚动劫持或正文动画。

- Animated List：借鉴明确选中、安静背景过渡及导航层级，在文档列表与个人页面导航中使用；书签形状是 Vana 的独立设计。
- 保持本地 React/CSS 实现，不新增 GSAP、图标包或动画框架；正文保持静止，尊重减少动画偏好。

## 账号职责

`/account` 统一管理登录、注册、邮箱确认提示、凭据读取失败、退出与本机文档复制。欢迎页提供入口，不再重复认证表单；桌面菜单、侧栏和手机顶栏均可到达账号页。邮箱确认返回账号页。手机顶栏原同步按钮的位置只保留一个账号入口，账号页没有手动同步或刷新操作，也不展示同步队列与时间。

设置页不再读取会话或执行登录/注册/退出，保留外观、备份、自定义服务和旧数据导入。账号仍调用原生认证接口，保持账号/项目范围校验、草稿提交和原有同步协议，不在前端自行存储会话。

主题选择保存在本机偏好中；读取失败或非法值回到默认主题，不影响使用文档。

## 验证边界

浏览器使用合成文档、测试邮箱与模拟 Tauri IPC，验证前端行为和布局；不将这些结果称为真实 Supabase 或原生凭据验收。Windows 原生脚本更新账号页路径，本轮未重跑三平台原生验收。

## 前端验收结果

- 类型检查、生产构建和 whitespace 检查通过。
- Playwright 在真实 Chromium 中检查登录失败、确认邮箱注册、直接登录注册、退出失败/成功、复制取消/确认、未配置服务、凭据库失败与邮箱回调路由；认证响应由模拟 IPC 提供。
- 从正文进入账号前能提交草稿；保存失败时不离开编辑页，草稿仍可见，重试后可正常导航。
- 账号表单在 320/390/768/1440 宽度未截断；390×844 手机的阅读、编辑、设置和历史预览通过；四主题、偏好重载、帮助的键盘展开和减少动画检查通过。
- `npm test` 的 23 项业务测试通过；Windows release 版本检查被本机 inotify 实例上限阻断，Tauri CLI 报 `Too many open files`。类型检查和构建均成功，此错误未通过修改测试或跳过断言掩盖。

## 阅读交互收敛

阅读模式不再用“请先进入编辑模式”文字 toast 或按钮 tooltip 提醒。准确点击正文中的文字时，编辑按钮使用当前主题的强调色高亮 1.8 秒，随后自动消退；正文继续保持只读，由用户主动点击编辑按钮进入编辑。切换文档、账号或模式会清除旧提示；开启减少动画时保留高亮颜色、关闭过渡。

点击判定要求主指针、左键或触摸，按压不超过 350 ms，全程位移不超过 6 CSS px，落点位于真实文本字符的范围内。空白、交互元素、拖动后返回起点、滚轮或滚动、长按、取消、多指、双击与文字选择均不触发。延迟 300 ms 确认，给第二次点击或文字选择留出取消时间；没有阻止默认滚动、选择或复制行为。

本轮检查：类型检查与生产构建通过；新增 6 项点击回归覆盖原生 PointerEvent 的原型属性、短按、移动往返、长按、取消、次要按钮及多指。Chromium 中检查鼠标和触摸；通过 CDP 输入真实触摸事件，触摸滚动实际移动正文 105 px 且没有高亮。账号入口、手动同步控件隐藏、只读保持、显式编辑与减少动画通过；模拟 IPC / RPC 验证后台自动更新完成且无成功提示。浏览器截图位于 `output/playwright/reading-*-highlight-*.png` 与 `account-quiet-mobile.png`。

本轮 `npm test` 共 30 项，29 项首次通过，Windows release 检查再次遇到宿主机 `Too many open files`。关闭本轮创建的 Chromium 会话后，单独重跑该检查通过；30 项均已完成验证，没有修改测试断言或系统限制。

此轮没有更新手机原生包，也没有运行真实 Supabase 验收；此前的 OnePlus 图标安装验收见 `docs/design/APP_ICON.md`。

后续完整 Android 包已更新到手机，账号入口、阅读精确点击、滑动与保存持久化完成真机验收，并修复长按菜单的返回行为。具体结果与测试边界见 [Android 真机验收](ANDROID_DEVICE_ACCEPTANCE_2026-10-14.md)。
