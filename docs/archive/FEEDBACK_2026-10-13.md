# 使用反馈落实记录

> 历史设计或验收记录，仅说明当时状态。当前功能与发布结论见 [文档索引](../README.md)。
来源：用户提供的朋友聊天截图。关于其他软件的描述作为需求线索，不作为已验证的竞品事实。

用户已明确：“权限问题”优先指让修改记录可查看、便于追溯。本轮以正文版本可见和可对照为验收重点；阅读模式作为防误改辅助功能，多人共享角色权限不纳入当前需求。

| 反馈 | 本轮实现 | 边界 |
| --- | --- | --- |
| 深层子条目返回时容易跳到主条目 | 完整父级路径，每级可点击；正文返回所在分组；分组返回上一级；手机点击文件夹进入该层，返回键逐层返回 | 根目录入口仍可明确点击；浏览器使用模拟 Tauri 返回事件验证，尚未在真机验收 |
| 权限问题（已确认重点是修改追溯） | 当前文档提供可查看的正文版本、记录时间与正文对照；账号隔离与阅读防误改提供辅助保护 | 当前记录不能识别修改者；多人共享角色权限属于独立需求；Android 返回监听权限属于原生实现，不代表产品协作权限 |
| 难以查看修改、担心无提示改动 | 新增当前文档的 SQLite 正文修改记录，按时间查看保留版本并切换对照打开记录时的正文；本机应用云端变化时记录前后正文 | 本机记录时间，不包含修改者身份；只记录正文；记录有保留上限，不是不可篡改审计；仍未提供恢复操作 |
| 每次阅读保存所有子条目造成冗余 | 阅读、分组导航、历史预览不调用正文保存；相同正文/标题/文本/标准化标签的原生保存直接返回原记录 | 原实现没有“阅读自动复制整棵子树”的路径；此次额外阻止相同内容重提交改时间、任务与历史；目录移动/删除仍需同步真实变化的子节点 |
| 按时清理存储即可 | 延续每文档 20 个版本、30 天和全空间历史 5 MiB 的保留策略；去掉相邻重复正文快照；永久删除同时清理该文档历史 | 策略在数据库操作时维护，没有后台常驻清理进程；SQLite 文件空闲页可复用，文件不一定立即缩小 |

## 验证

以下是首轮阅读与版本预览的验证记录。后续已实现正文差异、受保护的正文恢复、空间备份与冲突对照，上表“仍未提供恢复操作”仅描述首轮状态；最新验证及平台边界见 [开发记录](DEVELOPMENT_2026-10-13.md)。

- `npm run typecheck`、16 项前端测试、`npm run build` 通过。
- `cargo test -j 2 --locked --manifest-path tests/native-core/Cargo.toml`：20 项通过，新增相同保存不产生写入、云端正文记录/账号边界和保留/永久删除验证。
- Linux `cargo check -j 2 --manifest-path src-tauri/Cargo.toml` 通过，包括新增历史 IPC 与原生权限声明。
- 真实 React/Tiptap、模拟 Tauri IPC：桌面 8 个场景通过，覆盖深层路径、逐级返回、禁止阅读输入、版本预览与对照、零阅读保存、切回阅读前提交草稿。
- 手机浏览器 7 个场景通过，覆盖返回事件的分层行为、逐层进入文件夹、历史关闭顺序、版本预览、零阅读保存及横向溢出检查。
- 既有保存浏览器回归 6 个场景通过：A/B 内容与标签隔离、独立撤销、导出通知保留草稿、导航保存、原生关闭保存（IPC 模拟）；已适配显式进入编辑的交互。

本轮没有操作真实 Supabase，未进行 Android 真机安装或多人共享权限验证。自动化页面 fixture 和截图保存在本地 `output/playwright/`。
