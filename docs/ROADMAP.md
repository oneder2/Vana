# 下一阶段开发路线

决策基线：0.7.0。2026-10-13 用户指出界面暴露了大量不需要感知的工程内容；当前优先级改为阅读与写作体验收敛。下面的技术工作包保留为已完成工作的记录和未来约束，不再决定产品功能推进顺序。

## 开发方向

下一阶段先让用户顺畅完成三件事：找到文档、阅读与继续写作、在需要时回看修改。可靠保存、同步和备份支撑这些操作，工程指标与协议不进入默认阅读界面。

本轮在独立分支 `fix/writing-focus` 收敛欢迎页、正文页和设置页，并将账号登录与同步操作集中到独立账号页：默认突出正文、目录与编辑入口；高级配置和诊断按需展开；修改记录保留对照与恢复，保留策略放在可展开说明中；真实失败和覆盖风险仍明确反馈。具体规则见 [UI 方向](UI_DIRECTION.md)。

接下来先用实际日常写作反馈检查文档查找、编辑入口、自动保存反馈和手机布局。验收看用户能否独立完成操作、是否遇到干扰或误改，发现问题后再确定下一项改动。不能因为某个存储或同步模块已准备好，就默认增加新功能。

附件工作暂停，已有实现保留在实验分支 `feat/local-attachments`，不合入主线。云附件不再是默认下一步；是否继续取决于真实写作需求。多人共享权限、实时协作与端到端加密仍不进入当前范围。

## 第一个功能的实施切分

1. 在存储层添加历史列表、单版本读取和恢复接口，所有请求绑定 `expected_scope` 与文档 ID。现有历史只保存正文快照，界面必须明确只能恢复正文，不能声称恢复历史标签、标题或目录。
2. 增加所选版本与当前正文的差异展示。恢复同时校验 `content_generation` 与预览时的正文快照：当前代次主要保护远端应用，仅校验代次不能识别所有本地编辑。若预览期间正文变化，拒绝直接覆盖并要求重新预览；在同一事务保存当前正文、应用选定快照、更新代次并压缩 outbox。历史已过期、文档已永久删除或账号已切换时，返回明确错误。
3. 历史入口接入当前文档编辑流程；打开及确认恢复前 flush 草稿，恢复期间串行化该文档操作；预览使用编辑器同一正文渲染规则。确认后刷新当前文档，通知保留策略及恢复结果。
4. 增加有意义的回归场景：恢复与远端应用竞态、账号切换、注入写入失败、历史淘汰、恢复后再次编辑和同步。用真实 React/Tiptap 测试未保存草稿的保护，再在原生应用完成重启回读。

这四步分别形成存储契约、领域操作、用户入口和验收提交，便于检查和回退。复用已建立的草稿、事务和同步接口，不重新引入旧 Git 历史接口。

## 真实 Supabase 与设备验收

独立 PostgreSQL 回归使用 Auth stub，不能替代以下集成验证。使用专门测试项目、两个测试账号及两个客户端，不在生产数据上试验。

- 按完整迁移链升级已备份的旧数据；确认非法旧正文/目录有明确处理步骤，重复迁移可执行。旧客户端直接写入应被拒绝，新客户端保留本地数据并说明升级要求。
- 通过真实邮箱认证测试注册、登录、刷新、退出和项目切换；用其他账号的真实 JWT 验证 RPC/快照访问边界。
- 创建超过 1000 条记录，两端离线编辑后重连；同时移动目录、删除子树、编辑被删除节点，并模拟上行确认丢失。验收以完整数据和可见冲突副本为准。
- Linux/Windows 验证退出保存、重启、文件名和 PDF/DOCX/Markdown 输出；Android 验证 Release 安装、切后台/进程终止后重启和实际系统分享。区分正常关闭可 flush 与系统强杀不能保证 flush 的边界。

服务端迁移撤销旧协议写入权限，发布前必须给出客户端升级顺序和备份恢复方案；旧客户端不能直接回退到已经升级的新服务端。不要把构建成功当成设备测试通过，也不要用 Debug 证书包代替正式签名包。

## 架构调整原则

新增恢复和备份业务放入独立存储模块，`commands.rs` 保持薄 IPC 适配层。随这些功能提取主页文档选择/操作逻辑及账号、同步状态服务，保持空间标识、内容代次和事务 outbox 契约不变。Auth 与文档传输可逐步从 `supabaseSync.ts` 分离；凭据迁往原生层时再收拢会话刷新职责。

本轮保持已验证的固定快照分页协议。只有收集同步耗时、记录数、传输量和服务端开销后，再设计增量游标、删除日志保留及断点恢复；单用时间戳不能替代版本契约。实时协作、后台常驻同步、模板系统和更多平台暂不进入本轮。
