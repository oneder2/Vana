# Vana 空间备份 v1/v2

文件后缀 `.vana-backup.json`，UTF-8 JSON；无附件时使用 `version = 1`，包含本地附件时使用 `version = 2`，增加经过完整校验的 `attachments` 数组。当前文件上限 64 MiB、10,000 个节点；超过上限明确拒绝，不截断内容。v1 文件继续可读，v1 不得携带附件字段。

导出在当前账号空间的 SQLite 读事务中取得一致性快照。白名单字段只有：

- 文档和分组的正文、标题、父节点、层级、状态、收藏、模板标记、时间和标签名称。
- 标签名称和颜色。
- 保留的正文历史：文档 ID、正文快照、时间。
- v2 附件内容副本、原始文件名、MIME、大小、SHA-256 和创建时间；不含本机路径、上传凭据或云对象路径。

排除账号身份、会话/令牌、同步 revision、mutation ID、outbox、游标、永久删除的 tombstone 和本机冲突查看标记。v1 不含附件；v2 附件仍属于“仅此设备”内容，不产生云元数据。备份含明文正文；历史仅反映本机观察的有限版本，不是作者审计记录。

导入先完整反序列化并写入隔离的内存数据库，验证版本、字段、唯一 ID、时间、正文、标签及完整目录树。原子写入当前空间前再次验证；每次复制生成全新文档/历史 ID，重映射所有父节点，revision 从 0 开始，加入事务 outbox。不存在覆盖导入操作。

v2 导入还会验证每个附件的所属文档、文件名、扩展名和内容 magic/UTF-8、长度及 SHA-256；任一附件失败则整份备份不写入。复制导入生成新附件 ID，内容仍为本机副本，不产生同步任务或孤立云元数据。

现有同名标签保留当前颜色。导入历史沿用 20 个/文档、30 天、总共 5 MiB 的保留策略。预览显示文件内可保留条数，最终结果显示结合目标空间后实际保留条数。所有节点、标签、历史、限额检查及队列写入在同一事务，任何失败全部回滚。

Linux/Windows 保存到文档目录的 `vana` 子目录（不可用时为应用数据目录的 `exports`）；Android 保存到应用缓存的 `exports`，并提供系统分享入口。生成文件使用排他创建和 `sync_all`，同名文件加序号，不覆盖已有备份。Android 缓存可被系统清理，导出后应另存。附件单独导出时仍使用同一目录和文件名校验。
