# 产品方向

Vana 首先是一款服务个人阅读与写作的文档编辑器：让人容易找到文档、安静阅读、继续写作，需要时回看修改。离线保存、恢复、备份与可选同步支撑这个目的。用户已明确，“权限问题”当前优先指修改记录可查看、便于追溯。

## 可以建立的长处

| 使用需求 | Vana 的方向 | 当前证据与限制 |
| --- | --- | --- |
| 随时阅读和写作 | 访客离线空间、显式阅读/编辑、逐级目录导航 | 已实现；系统强杀前尚未提交的草稿不能保证保存 |
| 理解发生了什么变化 | 本地时间线、正文增删差异、版本排版对照 | 已实现；仅正文、有限保留、无修改者身份，不是防篡改审计 |
| 避免恢复覆盖新修改 | 先提交草稿，校验预览正文和内容代次，事务保存恢复前版本 | 原生回归通过；Android 恢复经真实服务同步至 Linux，并通过重启回读 |
| 保持数据可携带 | 空间备份、预览后复制导入、PDF/DOCX/Markdown 导出 | 已实现；备份为明文，当前不包含附件 |
| 理解同步冲突 | 保留副本、定位原文、按需对照 | 已实现本机关联；其他端/旧副本可能没有原文关联 |

这些是组合体验的建设方向，不宣称其它开源或商业软件缺少同类能力。成熟工具通常已有版本历史、备份和同步；Vana 需要用少量步骤、明确反馈及可验证的数据保护赢得使用价值，不能只靠主题和动画证明优势。

## 目标用户与验证

先服务个人笔记、草稿和长期文档阅读，保持 Linux、Windows、Android 与可选自托管同步。下一轮先观察用户能否独立找到文档、开始编辑、保存后返回阅读，是否被无关状态与提示干扰；修改记录与备份在需要时容易找到。以操作成功、错误可理解和数据完整作为验收依据，暂不设未经测量的性能或可靠性指标。

## 开发顺序

0.7.0 的真实同步与三平台验收已完成。按 [开发路线](ROADMAP.md) 优先收敛界面并验证日常写作体验，暂停附件与云附件推进；不将工程验收项直接转成产品页面。多人共享角色权限、实时协作、端到端加密分别需要独立设计；当前代码不提供这些承诺。

## 界面取舍

默认显示正文、目录、编辑与修改记录入口。同步队列、额度、服务来源、会话标识等留在按需展开的诊断中；同步失败、删除与恢复确认仍可见。功能说明只解释用户当前操作的结果。保持既有主题，不以更多面板或技术文案证明功能完整。账号相关操作集中到独立账号页，设置提供外观、备份与高级选项；实现和验收见 [界面优化](archive/UIUX_REFINEMENT_2026-10-13.md)。
